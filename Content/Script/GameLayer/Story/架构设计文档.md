# 时间循环叙事游戏 - 数据层架构设计

## 设计目标

为时间循环叙事游戏（如新绿镇故事）设计精简、干练的数据层，满足以下需求：
1. **LLM集成**：数据可直接序列化为Prompt或被FunctionCall修改
2. **条件驱动**：支持复杂的解锁条件和触发逻辑
3. **状态管理**：跟踪循环、NPC状态、玩家选择历史
4. **配置分离**：固定配置与运行时状态分离

## 数据分层设计

### 第一层：固定配置（DM_StoryConfig）

**存储内容**：游戏的静态配置数据，运行时不会改变

```lua
{
    background = "故事背景文本",
    theme = "时间循环",
    mainConflict = "主要冲突",
    
    scenes = {
        [sceneId] = {
            id, name, description, atmosphere,
            npcIds = {...},      -- 该场景的NPC列表
            choiceIds = {...}    -- 该场景的抉择列表
        }
    },
    
    npcTemplates = {
        [npcId] = {
            id, name, role, personality, motivation,
            background, dialogueStyle,
            initialStates = {trust, emotion, relation},
            tags = {...}
        }
    },
    
    choiceTemplates = {
        [choiceId] = {
            id, name, sceneId, description,
            unlockCondition = "条件表达式",
            effects = {
                npcStates = {...},
                sceneEvents = {...},
                globalFlags = {...}
            },
            resultNarrative = "结果描述"
        }
    }
}
```

**特点**：
- 所有配置存储在单独的配置文件中（如 `NewgreenTownStoryConfig.lua`）
- 通过 `BM_StoryConfig:ImportConfig()` 批量导入
- 可序列化为Prompt供LLM理解游戏设定

### 第二层：运行时状态（DM_StoryRuntime）

**存储内容**：游戏运行时的动态数据

```lua
{
    -- 循环状态
    loopCount = 1,
    currentSceneId = "scene_center",
    inDialogue = false,
    currentNpcId = nil,
    
    -- 解锁进度
    unlockedScenes = {[sceneId] = true},
    unlockedChoices = {[choiceId] = true},
    triggeredEvents = {[eventId] = true},
    
    -- NPC状态
    npcStates = {
        [npcId] = {
            id, trust, emotion, relation,
            currentIntent, tags, memories,
            currentScene
        }
    },
    
    -- 角色关系网
    relationships = {
        [npcId] = {[otherNpcId] = relationValue}
    },
    
    -- 物品和标记
    inventory = {[itemId] = count},
    globalFlags = {[flagName] = value},
    
    -- 选择历史
    currentLoopChoices = {...},
    allLoopsHistory = {
        {loopCount, choices = {...}}
    }
}
```

**特点**：
- 每次循环重置时，NPC状态恢复为初始值
- 选择历史被保存，供AI分析玩家策略
- 可序列化为Prompt供LLM理解当前状态

## 核心功能模块

### 1. 条件评估器（ConditionEvaluator）

**功能**：评估抉择的解锁条件、事件触发条件

**支持的条件表达式**：
```lua
-- 循环次数
"loopCount >= 2"

-- NPC状态
"getNPCStat('rex', 'trust') >= 50"
"hasTag('rex', 'angry')"

-- 物品
"hasItem('sunflower_seeds', 1)"

-- 事件
"isEventTriggered('rex_arrested')"

-- 全局标记
"getFlag('rexAngry') == true"

-- 复合条件
"loopCount >= 2 and not hasTag('rex', 'angry')"
```

**实现特点**：
- 使用Lua沙箱环境安全执行
- 提供丰富的辅助函数
- 支持AND/OR/NOT逻辑组合

### 2. Prompt构建器（StoryPromptBuilder）

**功能**：将数据转换为LLM可理解的Prompt

**构建的Prompt类型**：

1. **系统Prompt**（游戏开始时）
   - 游戏背景
   - 当前场景描述
   - 场景内NPC信息
   - 运行时状态

2. **NPC对话Prompt**（进入对话时）
   - NPC基础信息（性格、动机、对话风格）
   - NPC当前状态（信任度、情绪值、关系值）
   - 对话指导（根据状态值调整态度）

3. **可用抉择Prompt**（玩家请求时）
   - 自动过滤未解锁的抉择
   - 只显示满足条件的选项

4. **循环记忆Prompt**（AI理解上下文时）
   - 最近N次循环的选择历史
   - 当前循环已做的选择

5. **FunctionCall Schema**（配置LLM时）
   - make_choice：玩家做出抉择
   - update_npc_state：AI更新NPC状态
   - trigger_event：触发特定事件

## 数据流设计

### 游戏初始化流程

```
1. 加载配置
   ↓
   BM_StoryConfig:ImportConfig(NewgreenTownConfig)
   
2. 初始化运行时
   ↓
   BM_StoryRuntime:InitializeFromConfig(BM_StoryConfig)
   - 为所有NPC创建运行时状态
   - 解锁初始场景
   - 设置循环次数为1
   
3. 构建初始Prompt
   ↓
   StoryPromptBuilder.BuildSystemPrompt(...)
   - 发送给LLM，开始游戏
```

### 玩家做出抉择流程

```
1. 玩家选择抉择ID
   ↓
2. 条件检查
   ↓
   ConditionEvaluator.Evaluate(choice.unlockCondition, context)
   
3. 执行抉择
   ↓
   - 记录选择历史
   - 应用effects
     ├─ 更新NPC状态
     ├─ 触发事件
     ├─ 设置全局标记
     └─ 解锁新内容
   
4. 生成结果Prompt
   ↓
   - 使用choice.resultNarrative
   - 或让LLM生成叙事
   
5. 检查循环结束条件
   ↓
   如果玩家死亡 → StartNewLoop()
```

### 循环重置流程

```
1. 保存当前循环历史
   ↓
   allLoopsHistory.push(currentLoopChoices)
   
2. 重置状态
   ↓
   - loopCount +1
   - 清空currentLoopChoices
   - 清空triggeredEvents
   - 重置NPC状态为初始值（保留记忆）
   
3. 重新构建Prompt
   ↓
   - 包含循环记忆
   - 显示"这是第N次循环"
```

## 与LLM的集成方式

### 1. 游戏开始时

```lua
-- 构建系统Prompt
local systemPrompt = StoryPromptBuilder.BuildSystemPrompt(
    BM_StoryConfig,
    BM_StoryRuntime
)

-- 发送给LLM
LlmManager:SendMessage(systemPrompt, function(response)
    -- 处理AI的开场白
end)
```

### 2. NPC对话时

```lua
-- 开始对话
BM_StoryRuntime:StartDialogue("rex")

-- 构建NPC Prompt
local npcPrompt = StoryPromptBuilder.BuildNPCDialoguePrompt(
    BM_StoryConfig,
    BM_StoryRuntime,
    "rex"
)

-- 发送给LLM（让AI扮演雷克斯）
LlmManager:SendMessage(npcPrompt .. "\n玩家: " .. playerInput, function(response)
    -- 显示AI的回复
end)

-- 结束对话
BM_StoryRuntime:EndDialogue()
```

### 3. 玩家询问可用选项时

```lua
-- 构建可用抉择Prompt
local choicesPrompt = StoryPromptBuilder.BuildAvailableChoicesPrompt(
    BM_StoryConfig,
    BM_StoryRuntime,
    currentSceneId
)

-- 显示给玩家或让AI解释
```

### 4. FunctionCall处理

```lua
-- 配置LLM时提供Schema
local functionSchema = StoryPromptBuilder.BuildFunctionCallSchema()

-- LLM调用 make_choice
function OnFunctionCall_MakeChoice(choiceId, reason)
    local choice = BM_StoryConfig:GetChoice(choiceId)
    if not choice then return end
    
    -- 记录选择
    BM_StoryRuntime:RecordChoice(choiceId, currentSceneId, nil)
    
    -- 应用效果
    ApplyChoiceEffects(choice)
    
    -- 返回结果
    return {
        success = true,
        narrative = choice.resultNarrative
    }
end

-- LLM调用 update_npc_state
function OnFunctionCall_UpdateNPCState(npcId, statChanges, addTags, removeTags)
    -- 更新NPC状态
    for statName, delta in pairs(statChanges or {}) do
        BM_StoryRuntime:UpdateNPCStat(npcId, statName, delta)
    end
    
    -- 更新标记
    for _, tag in ipairs(addTags or {}) do
        BM_StoryRuntime:SetNPCTag(npcId, tag, true)
    end
    
    return {success = true}
end
```

## 优势总结

### 1. 精简干练
- 只存储核心数据，无冗余字段
- 配置与状态分离，职责清晰
- 数据结构扁平化，易于理解

### 2. 完美适配LLM
- 数据可直接序列化为Prompt
- 支持FunctionCall修改状态
- 提供丰富的上下文信息

### 3. 条件驱动
- 强大的条件表达式系统
- 支持复杂逻辑组合
- 安全的沙箱执行环境

### 4. 易于扩展
- 添加新场景：在配置文件中添加scene
- 添加新NPC：在配置文件中添加npc
- 添加新抉择：在配置文件中添加choice
- 添加新条件函数：在ConditionEvaluator中扩展

### 5. 符合项目架构
- 遵循DataModule + BusinessModule模式
- 遵循Manager + System模式
- 可集成到现有的GameContext和EventCenter
